Cross-links

  • A Call links to its service, its operation's form filled with the same input, and its resource where one can be identified.
  • A resource links to the Calls that name it, and to its service's operations.
  • A Marker's added resources link to their pages; removed ones link to Calls that name them.
  • An empty list links to Calls seen in other Regions when there are any.
  • Calls and Current run link to Setup's Gateway page while no Call has been recorded.

Navigation specification

Global navigation holds five places: Current run, Calls, Services, Markers and Setup. It is on every page, with Find, the Active Region, the connection state and Set a Marker. Within Services, a service's Resources, Operations and Calls form local navigation beneath global navigation.

  • Location. The page title names the item; the path above it names its service. The current place is marked in both levels of navigation.
  • Addresses. Every service, resource, operation, Call and Marker has an address that can be copied. A service's address uses its SDK ID.
  • Region. The Active Region applies to resources and Markers. Calls come from every Region and show their own.
  • After a restart. Current run says state was lost. Earlier Calls stay under their own run; earlier Markers are ended and cannot be compared.
  • Narrow windows. At 640 px one pane shows at a time, and going back returns to the list at the same position. From about 1,100 px a list stays beside its detail; from about 1,700 px the request and response stay open as a third pane. Global navigation collapses to its five icons with names available to keyboard and screen reader users, and Find stays visible.

Labeling guide

  • Services take the title in their Service Model without a leading "AWS" or "Amazon", followed by the SDK ID: "Step Functions · SFN". The SDK ID tells apart services that share a title; where the two are the same, it is shown once. Table rows use the SDK ID alone.
  • Operations and fields keep their exact API names: "ListStateMachines". They match the Developer's code.
  • Resource lists take the noun of the operation that fills them: ListStateMachines becomes "State machines". Where two lists would share a noun, both show the operation name.
  • Send is the verb for an operation. Run only ever means an Emulator Run.
  • Not implemented names the Emulator version it describes: "Not implemented in 1.0.509". "Not offered" marks an operation in the model that the Emulator's own list lacks.
  • A new place takes the noun for what a person finds there, in the glossary's words. Containers such as Dashboard, Explorer or Resources never name a top-level place.

Search and browse strategy

Search

Find is for a name the Developer already has. It matches service titles, SDK IDs, signing names and operation names, and opens from any page with the keyboard. Services rank above operations, and services seen this run rank first. Results show the title and SDK ID together, and unimplemented operations are labelled. Find covers names and not the resources inside services, since that would mean asking all 436.

Browse

Services seen this run come first: those with Calls, and those opened. The full A–Z list follows, with a filter by name and filters for Curated Services, services with a resource list, and services with every operation implemented. Within a service, operations group by verb and filter by name and implementation.

No results

Find offers the closest names by spelling, the A–Z list, and, for one of the three modelled services the Emulator lacks, a line saying so.
