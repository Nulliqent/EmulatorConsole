Problem Statement

Six tasks, from opening the Console to closing the question that opened it: connect, explain a failed call, reach any service, send an operation, see what a run created, and carry on after the Emulator restarts. Why they matter is in the brief.

User Context & Variations

  • No Gateway. There are no Calls. Services, Operations and Markers work in full; Current run and Calls lead to Gateway setup.
  • Arriving from a failed test. The Developer has an error name or a time. Calls opens newest first, and its filter takes an error name, an operation or a status.
  • A Curated Service. Resources holds pages made for that service, with its test actions, delete and purge. Every other service's lists are read-only.
  • Beside an editor at 640 px. One pane at a time. Opening a Call replaces the list, and going back returns to the same row.

Setup: Connection

It exists because nothing else works until the Emulator answers. The Console reads the address and keys it was started with and tries once on open. Success moves on by itself. Failure names which of three things failed, reaching the address, trusting the certificate or reading the keys, with the command that fixes it and Try again.

Current run

It says whether anything has happened. With no Calls it offers Gateway setup and Services side by side, neither blocking the other.

Setup: Gateway

It exists because recording must be understood before it starts. It states what is recorded, then gives the endpoint line for the SDK. The page waits and reports the first Call when one arrives. A browser-originated request is refused, and the page says so.

Calls

It exists to find one request. Failed Calls are one filter away, and from Current run one step. A Call that is not listed may have gone straight to the Emulator, including through a URL the Emulator returned; the page says so and links to Gateway setup.

Call

It exists to separate the Developer's mistake from the Emulator's. The error as received comes first, then the Verdict with the evidence it rests on, then the request and response. Request Rejected leads to the input. Emulator Gap, given for 501, for UnknownService, and for InvalidAction naming an operation the model defines, leads to the operation, which carries the same label. Unclear says which evidence is missing and leads to the request and response. Bodies cut at 256 KB say so.

From a Call to a retry

Open in operation form carries the same input, and the Developer edits and sends it. The result is a sent operation and not a Call, so it never changes the list being examined.

Find

It exists because 436 services cannot be scanned. A service name leads to the service; an operation name leads to its form.

Service: Resources

It exists to show what is there. Each list the model offers is one choice, and only the one chosen is read. Past seven, the choices become a list that can be filtered. Four endings look different: resources, none in this Region, not implemented, and could not be read. None in this Region names other Regions where Calls were seen.

Service without a list

It opens on Operations, and Resources says which input its lists need and leads to those operations.

Resource

It exists to show everything returned for one item. Details come from a matching describe or get operation when there is exactly one; otherwise the fields from the list are shown, and the page says so. Calls that name the resource are one step away.

Operations

It exists to show what a service can do and what the Emulator lacks. Unimplemented operations stay listed and labelled.

Operation form

It exists to make a valid request without reading the API reference. Required fields come first and optional fields open on request. Fields and JSON are two views of one input. An input that breaks the model is marked and can still be sent, because seeing the Emulator's refusal is sometimes the point.

Confirm

It exists only for Destructive Operations. It names the operation, the resource and the Region. A single delete takes one confirmation; purging names the count where the service gives one.

Response

It exists to show what came back, unchanged. The same Verdicts apply here as on a Call. The input stays for editing.

Set a Marker

It reads the top-level resources of the Curated Services in the Active Region, then confirms with the time. While it reads, it says which service it is on; a service that cannot be read is named and left out.

Marker

It exists to answer what changed. It reads again on opening and on request, and shows added and removed resources by service. It says that it compares the eight Curated Services, in one Region, and not objects, items or messages.

Restart notice

It exists so an empty list is not read as a bug. It says resources were lost and the earlier Markers ended. New keys are what shows that a run is new, so the time given is when the Console noticed. When the Emulator is stopped, it shows docker compose restart. Earlier Calls stay under their own run.
